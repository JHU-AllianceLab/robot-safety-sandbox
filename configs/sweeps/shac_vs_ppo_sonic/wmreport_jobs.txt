# The report run: one consistent dataset for the WM-filter report (episodes without the
# fallAndGetUp and sprint clips, kick |dv| ~ U(0, 4) m/s at the start, sensor noise OFF).
# Per SHAC seed, in order (array task s+1 of wmreport_seed.sh runs jobs 3s+1 .. 3s+3):
#  1. calibration (--seed 1 lists, 2048 episodes, disjoint from the evaluation's): SONIC up to
#     a decision step ~ onset + U{0..50}, one noise-free WM rollout of "u_SONIC, then SHAC" (3 s)
#     and the real same; records predicted / real g AND the margin's height / tilt inputs;
#  2. calibrate_wm_min_tube.py: eps_H(c) of the worst margin, H = 0.1 / 0.4 / 1 / 3 s;
#  3. evaluation (--seed 0 lists, 1024 episodes): SONIC, SHAC, the exact CPU filter (1 s) and
#     the WM tube filter at 0.4 / 1 / 3 s (c = 0.95), the 1 s one also with latch 1 s / 2 s
#     (+dwell: SHAC holds >= that long after each hand-over) and latch forever.
# The critic frame is refreshed after the kick, so the WM rollouts start from the kicked
# state (before 2026-11-04 they saw it one step late; that run is in wmreport_prefix/).
# Smoke test first (wmreport_smoke.sh), then:
#   sbatch -A hhu49_alliance1 -p l40s,rtx6000,h100 --array=1-3 --gres=gpu:1 --cpus-per-task=32 --mem=96G --time=01:30:00 --job-name=wmreport --output=logs/slurm/%x_%A_%a.out configs/sweeps/shac_vs_ppo_sonic/wmreport_seed.sh
